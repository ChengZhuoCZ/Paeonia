# Protocol 04b — Grand Introduction Narrative Realization


> **Optional extended module.** Invoke only when Protocol 04 has selected the compatibility ledger route. Do not use it to add narrative layers to an ordinary Introduction. The `IntroductionCoreBrief`, earliest intelligible theorem, and reader contract remain controlling.

## Purpose

Translate the high-level `IntroductionNarrativeLedger` into a research-article narrative that is ready for paragraph architecture. This protocol does **not** directly polish or paraphrase an existing Introduction, and it does not yet write final publication prose.

The key distinction is:

`narrative truth → paragraph architecture → prose`

Skipping the middle layer is a common source of generic, slot-filled Introduction prose.

## Inputs

Required:
- closed `MathLedger`;
- passed `ProofCoreGateReport`;
- finalized theorem framing / semantic checksum;
- `IntroductionNarrativeLedger` from Protocol 04a;
- `MathematicalStoryLedger` from Protocol 04n only when the selected extended route depends on an operative parent program or scale/category transition.

If literature or priority claims are used, the relevant entries must be verified or explicitly flagged before release.

## 1. Enforce from-scratch reconstruction

If the mathematical source contains an existing Introduction:

Allowed extraction:
- mathematical claims;
- citation candidates;
- terminology;
- historical assertions requiring verification.

Forbidden inheritance:
- sentence wording;
- paragraph sequence;
- theorem latency;
- literature order;
- adjacent-problem order;
- rhetorical escalation;
- organization-paragraph structure.

The final Introduction is generated from the closed mathematics and verified literature, not by polishing the source Introduction.

## 2. Opening movement

Open at the largest mathematically operative scale supported by the core brief and, when triggered, `MathematicalStoryLedger`. The opening should normally expose a parent program, canonical principle, structural tension, or limiting-to-exact gap before it exposes routine notation. Do not begin with generic prestige claims or a ceremonial history sentence.

For specialist research prose, also ask whether the standard object actually needs definition in the Introduction. A familiar PDE, spectral problem, Sobolev space, or physical interpretation should be compressed unless it is part of the paper's novelty or needed to state the result.

## 3. Carry the larger story through the narrowing

For an ambitious Introduction, narrowing is not `general field → smaller field → exact theorem`. It is a sequence of mathematical state changes. Use the primary story archetype from `MathematicalStoryLedger`, for example:

`canonical principle → restricted class → lost mechanism → exact frontier`,

`limiting theorem → finite approximation → asymptotic selection → exact finite gap`, or

`local theory → degeneration/global obstruction → global target`.

Every paragraph should make the eventual theorem more necessary.

## 4. Narrow to the exact problem

Every planned paragraph in the narrowing phase must reduce uncertainty. Move from field → classical axis → current frontier → exact target only through mathematically necessary steps.

When a conjecture motivates the paper, distinguish clearly:
- what the conjecture asserts;
- what was previously known;
- what remains open;
- exactly which implication, subproblem, or evidence the present theorem supplies.

## 5. State the obstruction before advertising the method

Before introducing the paper's mechanism, tell the reader what fails in the natural approach whenever this is mathematically meaningful.

Prefer:

`natural route → required property → precise obstruction → replacement viewpoint`

rather than:

`this is difficult → we introduce a new method`.

## 6. Present the theorem ladder in reader order

The theorem order in the Introduction may differ from proof order. Choose the order that makes the contribution easiest to understand.

A genuine ladder may take forms such as:
- conjecture → structural theorem → quantitative engine → global theorem;
- main theorem → sharp quantitative refinement → rigidity/equality;
- local/large-parameter theorem → effective estimate → global closure.

Do not invent a ladder when there is only one genuine main theorem.

## 7. Re-expand only with a mathematical purpose

After the principal result is clear, re-expand to the parent mathematical program identified in `MathematicalStoryLedger` before moving to optional broader consequences. Re-expansion may:
- locate the theorem within a conjectural picture;
- compare the mechanism with a neighboring theory;
- identify a reusable representation or method;
- expose a consequence not obvious from the theorem statement.

This stage is interpretation, not a second literature review.

## 8. Literature is grouped by mathematical function

Convert `LiteratureLandscape` items into claim-centered clusters before prose drafting. Do not carry the ledger's item-by-item storage order into sentences.

A cluster should establish one of:
- origin;
- benchmark;
- frontier;
- obstruction;
- adjacent bridge;
- technical precursor.

If several papers support the same mathematical proposition, they may appear together. If two papers play different roles, separate them even if chronologically adjacent.

## 9. Mechanism before itinerary

Build a causal proof story from the closed proof graph that explains how the argument crosses the primary scale transition or structural tension recorded in `MathematicalStoryLedger`. Prefer transformations, reductions, estimates, and closure principles. A section itinerary is optional and secondary.

## 10. Output

Pass the realized narrative to Protocol 04d and build `IntroductionParagraphPlan`. No final Introduction prose is written yet.
