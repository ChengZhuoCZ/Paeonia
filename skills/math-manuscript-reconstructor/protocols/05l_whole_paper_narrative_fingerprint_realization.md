# Protocol 05l — Whole-Paper Narrative Fingerprint Realization

## Purpose

Realize a fresh whole-paper architecture from the closed target proof graph. When a style corpus supplied a `WholePaperNarrativeFingerprintLedger`, use only its supported abstract global narrative traits as an optional prior. Without a style corpus, the universal whole-paper architecture rules in this protocol remain fully active.

This protocol runs **after `ProofCoreGate`**. It never rearranges mathematics to imitate source-wide proportions or chronology.

## 1. Build the paper spine first

From the closed `ProofGraph`, identify:

- the main-result node(s);
- the minimal reader prerequisites for stating them;
- the reusable engines;
- the true technical pressure peaks;
- regime splits and rejoin points;
- equality/rigidity/classification endgames;
- consequences that genuinely deserve body space;
- modules that pass the appendix necessity test.

Choose a global-spine label as a description, not a template.

## 2. Place the main result

Expose the principal result as early as it can be stated accurately and readably.

- If notation is already standard, use `EARLY_READABLE_STATEMENT`.
- If a few definitions are essential, use `MINIMAL_SETUP_THEN_STATEMENT`.
- If several coequal results form the paper's contribution, use `RESULT_MAP_FOR_MULTI_THEOREM_PAPER`.

Do not postpone the main statement until the section in which it is proved merely because the proof occurs later.

## 3. Place the technical core by dependency pressure

Map each proof engine to body sections only after evaluating its independence and reuse.

Do not distribute technical lemmas evenly. If one argument is the genuine core, let that region dominate. If two methods are genuinely distinct, preserve two peaks. If regimes split, let the paper reflect the split and later rejoin.

Never enlarge light sections or compress delicate sections to create visual balance.

## 4. Generate section architecture from the whole spine

Invoke `protocols/05j_section_narrative_fingerprint_realization.md` inside the global architecture.

Whole-paper decisions dominate local symmetry preferences. For example:

- a section may remain very short if it performs a necessary synthesis;
- a technical engine may occupy several subsections if internal re-entry matters;
- a proof endgame may be only one section even if the preceding engine spans several;
- a final application does not need a matching companion section.

## 5. Front matter after architecture, from the proof ledger

Write the Introduction only after the body architecture and theorem frame are fixed. For substantial papers, first build `IntroductionCoreBrief` under Protocol 04 and select one theorem-facing arc. Use `IntroductionNarrativeLedger` only when multi-thread complexity justifies the extended compatibility route.

The Introduction may include a wider classical/conjectural arc than the body, but only through verified literature and only when it sharpens the theorem's position. It should expose the exact result, real obstruction, reader-facing theorem hierarchy, broader significance, and proof mechanism without mirroring every body section.

Prefer a mechanism map over an administrative contents paragraph. Run the reader-contract audit after realization; run `GRAND-NARRATIVE-INTEGRITY` only when a grand/program-level module was deliberately triggered. Write the Abstract after the Introduction and compress one level further.

## 6. Appendix decision table

For every proposed appendix, record:

- `owner`: which body result(s) need it;
- `role`: toolbox, local technical module, reference foundation, verification, extension, or certificate;
- `mechanism_centrality`: central / supporting / optional;
- `body_import`: the exact statement imported into the body;
- `why_not_body`: the mathematical reason for separation;
- `reader_can_follow_main_mechanism_without_appendix`: yes/no.

Reject an appendix if:

- its only reason is length;
- it contains the paper's unarticulated central idea;
- it becomes proof-debt storage or hides an audit blocker;
- it contains equality/rigidity logic essential to understanding the theorem;
- it survives only because the source had it.

## 7. Whole-paper asymmetry audit

Review the paper's mass map qualitatively.

Flag for review when:

- all substantial sections are suspiciously similar in size and formal-result density;
- every technical section is paired with a conceptual section despite no mathematical need;
- every section has the same internal theorem/lemma cadence;
- the paper contains a ceremonial short section only to improve visual symmetry;
- the Introduction duplicates a body overview section;
- the proof has closed but a generic conclusion repeats the abstract/introduction.

A flag is not an instruction to randomize lengths. Repair only by re-evaluating mathematical obligations.

## 8. Global cold-author pass

After local `COLD_AUTHOR`, perform one whole-paper pass with mathematics frozen.

Ask:

1. Is this section necessary for the proof spine, interpretation, application, or reference?
2. Is the main theorem exposed earlier than it needs to be hidden, but no earlier than it can be read?
3. Does the Introduction explain the mechanism without replaying the body?
4. Does every appendix have a modular reason?
5. Are there duplicated orientation sections?
6. Does the paper end when the mathematics ends?

Allowed global edits:

- delete redundant orientation sections;
- merge sections that carry one obligation family;
- move genuinely modular material to an appendix;
- return central mechanism-bearing material from an appendix to the body;
- compress front matter;
- remove ceremonial conclusion prose.

Any edit that changes proof semantics forces rollback to the proof layer.

## 9. Fidelity conditions

Pass `WHOLE-PAPER-NARRATIVE-FIDELITY` only if:

- the global spine is induced by the target dependency graph;
- main-result exposure is justified by readability/prerequisites;
- technical mass follows actual proof pressure;
- front matter is a compressed semantic projection of the closed body;
- appendices pass the modularity test;
- global asymmetry is mathematics-driven;
- no source-wide chapter/section sequence, ratio, or mass profile was copied.
