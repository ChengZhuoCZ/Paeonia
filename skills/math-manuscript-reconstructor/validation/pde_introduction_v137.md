# v1.37.0 Conditional PDE Introduction Validation

## Scope

This release preserves the v1.36 reader-first Introduction path and adds a conditional PDE extension inside `IntroductionCoreBrief`. It does not add a mandatory PDE ledger or a target Introduction length.

## Corpus basis

The editorial rules were compared against representative Introductions from Buckmaster–Vicol, Figalli–Serra, Chodosh–Mantoulidis, Bedrossian–Masmoudi, Kenig–Merle, Armstrong–Silvestre–Smart, and Kiselev–Nazarov–Volberg. The stored corpus report records bibliographic anchors and abstract decisions only; no source prose or paragraph sequence is used as a template.

## New contract surface

- theorem coordinates: equation/setting, regime, solution class, topology, and conclusion;
- multi-axis result delta with incomparable frontier nodes allowed;
- result architecture separate from narrative arc;
- theorem-presentation modes governed by prerequisite burden;
- structural, technical, normalization, and proof-local assumption roles;
- short causal obstruction stack;
- formula meaning → adverse effect → unlocked control → closure interface;
- typed theorem, method, known-obstruction, and open boundaries;
- genre-specific checks for continuation, nonlinear closure, singular limits, nonuniqueness, and stratification;
- explanatory burden rather than venue prestige as the length policy.

## Limits

These tests verify internal package contracts and selected editorial decisions. They do not establish mathematical correctness of an arbitrary paper, predict referee response, certify “top-journal style,” or replace a theorem-aware cold read. The corpus is deliberately heterogeneous, so the package encodes conditional choices rather than an average template.
